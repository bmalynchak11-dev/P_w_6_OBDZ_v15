# Відповіді на контрольні питання (Варіант 15)

### 1. Яким видом підзапиту ви скористалися і чому саме ним?
У роботі використано **корельований табличний підзапит із предикатом `NOT EXISTS`**.
* Він є корельованим, оскільки внутрішній запит залежить від зовнішнього через умову зв'язку по ключу (`dev.department_id = d.id`).
* `NOT EXISTS` вибрано тому, що це надійний шаблон «анти-з'єднання» (anti-join). Його завдання — повернути істину (`TRUE`) лише тоді, коли підзапит для поточного рядка повертає порожню множину (тобто для підрозділу немає пов'язаних приладів). Крім того, СУБД оптимізує виконання: для повернення результату підзапиту достатньо знайти хоча б один збіг (short-circuit evaluation).

### 2. Чи можна записати вашу задачу без підзапиту і що зміниться?
Так, задачу можна реалізувати за допомогою зовнішнього з'єднання `LEFT JOIN`:
```sql
SELECT d.name, d.parent_id
FROM department AS d
LEFT JOIN device AS dev ON dev.department_id = d.id
WHERE dev.id IS NULL;

Семантично запит перетворюється з фільтрації рядків за умовою існування на фізичне з'єднання двох наборів із наступним відсіканням рядків, що містять NULL.

У сучасних оптимізаторах PostgreSQL (зокрема версії 18) плани виконання для NOT EXISTS та LEFT JOIN ... WHERE dev.id IS NULL найчастіше зводяться до однакового вузла Hash Anti Join. Проте форма NOT EXISTS чіткіше виражає бізнес-логіку («показати підрозділи, де немає приладів») і захищена від проблем із випадковим дублюванням рядків при відсутності коректного ключа.

### 3. Що станеться з вашим запитом, якщо в підзапиті з'явиться NULL або порожній результат?
Порожній результат підзапиту: Якщо для підрозділу немає жодного приладу, підзапит повертає 0 рядків. Предикат EXISTS повертає FALSE, а заперечення NOT EXISTS стає TRUE — підрозділ потрапляє у фінальну вибірку (що й вимагається за логікою завдання).

Поява значень NULL: На відміну від конструкції NOT IN, яка при наявності хоча б одного NULL повертає UNKNOWN і обнуляє всю вибірку, конструкція NOT EXISTS перевіряє виключно наявність рядків у результаті (SELECT 1), ігноруючи значення стовпців. Навіть якщо в стовпцях таблиці device будуть значення NULL, NOT EXISTS продовжить повертати коректний результат.
